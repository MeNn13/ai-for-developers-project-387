# 0004. Доверенный издатель реализации отдельно от модели и ревью

Дата: 2026-11-15. Статус: принято для инфраструктуры #38/#40.

## Контекст

Модель готовит изменения по согласованной спецификации, но её результат и код
ветки не являются доверенными управляющими инструкциями. Выдача записи модели
позволила бы менять workflow, проверки и собственные ограничения. GITHUB_TOKEN
также не обеспечивает ожидаемый запуск CI при собственных публикациях.

## Решение

Исполнение, проверка результата, публикация и независимое ревью разделены.
Издатель запускает только точную доверенную ревизию main, не исполняет артефакты
и выполняет фиксированные GitHub API операции через отдельный App без Workflows.
Данные результата ограничены обычными файлами приложения; служебные пути
отклоняются при добавлении, удалении и переименовании.

Независимое свидетельство связывает полный check с digest результата и SHA
коммита. Издатель восстанавливает tree/commit из данных и сверяет SHA до изменения
ref. Право обновления ветки определяется доверенным receipt Actions и точной
идентичностью App; имена веток и текст комментариев недостаточны. Чужой head
останавливает операцию; force, reset и переписывание истории запрещены.
Один сеанс реализации получает полную спецификацию и редактирует отдельную
копию базового дерева без Git. Контроллер вычисляет и проверяет изменения,
запускает генерацию и проверяет один коммит на его точном SHA в отдельной
изоляции без ключа модели. В одном задании публикации App создаёт PR на
полном проверенном коммите и переводит его в Ready.

## Последствия

App устанавливает человек только в один репозиторий; приватный ключ хранится в
environment издателя. Producer обязан изолировать модель от контекста, проверки
и их артефактов. При утрате истории или неоднозначном частичном сбое нужен человек.
Узкий список файлов ограничивает автоматизацию инфраструктуры и зависимостей:
они требуют отдельного человеческого PR. Фикстуры не заменяют живую проверку App.
После публикации независимое ревью читает `REVIEW.md` и оставляет комментарий.
Решение о последующих изменениях и мерже принимает человек.

Конкретная процедура и контракт находятся в
[руководстве издателя](../github-agent-publisher.md). CI-термины не входят в
доменный словарь календаря. Бюджет, свежий допуск Re-run и оркестрация внедряются
в #41; ручная граница #40 сама по себе не завершает #38.
